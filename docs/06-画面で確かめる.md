# 画面で確かめる — メッセージウィンドウ検査台

校正で最後にものを言うのは、**データ上の文字列と画面の見た目を突き合わせる**
作業です。実務では実機か開発ビルドでこれをやります。このリポジトリでは
`tools/make_viewer.py` が同じことをする画面を作ります。

```bash
python3 tools/make_sample.py      # まだなら
python3 tools/make_viewer.py
# → work/viewer.html をブラウザで開く
```

外部への通信は一切しない 1 枚の HTML です。フォントは `work/FONT.BIN` の
グリフをそのまま埋め込んで canvas に描いているので、**画面に出ている文字は
ゲームが持っているグリフそのもの** です。だからフォントに無い文字は
本当に □ になります。

## 画面の構成

| 場所 | 中身 |
| --- | --- |
| 左 | メッセージ一覧。ERROR / WARN の点で絞り込める |
| 中央 | 320x240 の画面と、送り・前後の操作 |
| 中央下 | 表示条件と、現在のページの行ごとの幅 |
| 右 | ID・オフセット、タグ入りテキスト、校正チェック、元データの 16 進 |

## 操作

| キー | 動作 |
| --- | --- |
| `Space` / `Enter` | 送り。`<WAIT>` で止まり、押すとウィンドウが消えて次のページへ |
| `←` `→` | 前・次のメッセージ |
| `R` | 頭から |
| `T` | 原文 / 訳文 の切り替え |

`<CLEAR>` でウィンドウがクリアされ、`<COLOR:xx>` で文字色が変わり、
`<VAR:00>` にはプレイヤー名の欄に打った文字列が入ります。
制御コードが実際に何をするのかは、これを一度触ると腹に落ちます。

## 何が見えるようになるか

`exercises/qa_target.tsv` を題材にしているので、**原文 / 訳文 を切り替える
だけで仕込んだ不具合が画面の崩れとして見えます。**

| id | 訳文に切り替えると | 対応するチェック |
| --- | --- | --- |
| 30 | 「扉には□□の□□が□まれている。」 | `font` — 薔薇・紋章・刻 がフォントに無い |
| 12 | 4 行目の「どうする？」が枠の下に赤く落ちる | `line_count` |
| 9 | 1 行が枠の右を突き抜けて画面の端で切れる | `line_width` |
| 2 | プレイヤー名が出ず「あなた！」になる | `placeholder` |
| 13 | 「〜」が □ になる | `font` + `notation` |
| 16 | 「ﾀﾁ」が □□ になる | `halfwidth` |

「仕様違反」という指摘が、画面上の何に対応しているのかが同時に分かります。
逆にいうと、**この画面を見ずに数字だけで指摘を書くと、開発側に伝わりません。**

## 変数の長さを試す

いちばん実務向きの使い方がこれです。原文に切り替えて id 2 を出し、
プレイヤー名の欄を `ながいなまえ` に変えてみてください。

```
<VAR:00>！　こんなところにいたのね。
```

タグの状態では 14 文字ですが、6 文字の名前が入ると 20 文字になり、
末尾の「ね。」が上限の 18 文字を越えて赤くなります。差し込まれた文字は
水色で描かれるので、どこが変数由来かが区別できます。

[04-校正とQA.md](04-校正とQA.md) に書いた `proofread.py` の弱点
(変数の幅を 0 として数えている) が、そのまま目で確認できる状態です。
**「名前は最大何文字か」を仕様として最初に確認する** 理由がここにあります。

## 表示条件のスイッチ

* **文字マスを表示** — 16x16 のマス目を重ねる。1 文字 = 1 マスであることの確認
* **枠の上限を表示** — 18 文字目の右端と 3 行目の下端にかぎ括弧を出す
* **変数の差し込みを色分け** — `<VAR:xx>` 由来の文字を水色にする
* **文字送りの速さ** — 0 にすると一括表示。速度による読みやすさの差も見られる
* **拡大率** — ×1 で実寸。ドット単位で見たいときは ×3

## 別の題材を見る

`--tsv` で任意の TSV を読み込めます。課題 6 で自分が直したファイルを
そのまま画面で確認するのが本来の使い方です。

```bash
python3 tools/make_viewer.py --tsv work/qa_fixed.tsv -o work/viewer_fixed.html
```

独自文字コードのファイルから抽出したものでも同じように見られます。
フォントは共通なので `--tsv work/MSG_ENC.tsv` でも動きます。

## 実機での確認との違い

この画面はあくまで再現です。実機で追加で見る必要があるのは次のあたりです。

* 実際の背景の上に置いたときの可読性 (ここでは固定の夜空を描いているだけ)
* ウィンドウの透過や縁取りの実装差
* 文字送り中に改行が入るタイミング
* コントローラの入力受付との兼ね合い

それでも、**「枠に入るか」「表示できる字か」「変数で伸びないか」の 3 点は
この画面でほぼ判定できます。** 実機に上げる前に落とせるものを落とすのが、
この工程の目的です。
