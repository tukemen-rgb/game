# 僕の夏休み 2 のテキストを取り出す手順 (通し)

構造探査台と `tools/boku2.py` を使って、吸い出したフォルダから会話テキストを
校正用の TSV にするまでの、順番どおりの手順です。判明した形式の説明は
docs/09、法律面の注意は docs/05 を先に読んでください (取り出したデータや
訳文を配布することは、はっきり問題があります)。

先に **練習用データで一周** しておくと、実物で迷いません:

```bash
python3 tools/make_boku2_sample.py      # work/BOKU2SAMPLE/ に同じ形の架空データ
```

以下、`実物` と書いた所を `work/BOKU2SAMPLE` に読み替えれば、そのまま通ります
(練習用のフォント画像は模様なので、文字表は付属の `font.txt` を使います)。

用語: この文書で **文字表** と呼ぶのは、docs/01 の「文字テーブル」をフォント画像の
並び順でそのまま作ったものです (番号 = 画像の何番目の文字か)。**入れ物** は
「項目数 + 位置と長さの表」で部品をまとめたファイル、**索引** は本体とは別の
ファイルに置かれた一覧 (`BOKU2.IDX`) を指します。

## 0. 手元にあるもの

吸い出したフォルダ (`SYSTEM.CNF`, `SCPS_150.26`, `BOKU2.IDX`, `BOKU2.IMG`,
`MAP/`, `BGM/`, `VOICE/`)。テキストは次の 2 か所にあります。

| 場所 | 中身 | 読み方 |
| --- | --- | --- |
| `BOKU2.IMG` の中の `system/**/*.msg` | メニュー・道具・釣り・虫の名前など | 索引で切り分けてから `.msg` として読む |
| `MAP/*.*` の各ファイルの 1 番 | 物語の会話 (本体) | 入れ物を切り分けてから `.msg` として読む |

## 0.5 まず診断 (1 コマンド)

```bash
python3 tools/boku2.py check 実物/
```

索引・本体・フォント・MAP を一通り診て、**報告用の要約**を出します (ゲームの本文は
出しません)。「問題なし」なら次へ。`→` の行が出たら、その出力ごと貼って報告すれば、
先頭 16 バイトなどの手がかりが含まれているので次の手が打てます。

Python を使わない場合は、構造探査台の「索引ファイル」タブで解析したあとに出る
**「報告用の要約を作る」** が同じものを出します (MAP のファイルも一緒に読み込んで
おくと MAP まで診ます)。

## 1. 画面で確かめる (構造探査台)

1. **フォルダごと読む** で吸い出したフォルダを開く。
2. 「索引ファイル」タブ → 索引 `BOKU2.IDX` / 本体 `BOKU2.IMG` → **解析する**。
   「候補 1 件 (DFI 形式として読みました)」と出れば正解。
3. **この解釈で N 個に切り分ける** を押す。一覧に `system/system.msg` のように
   フォルダ付きの名前が並ぶ。
   - `#0012.tm2` のように番号だけなら名前の読み取りに失敗している。
     `BOKU2.IDX` の 16 進表示で、レコードの終わり (0x8140 付近) を見て報告する。
4. 一覧の絞り込みに `msg` と入れ、`system.msg` を選ぶ →「既知の形式」タブ →
   **このファイルを .msg として読む**。件数と、各行の文字番号 `[123]` が並ぶ。
5. 絞り込みに `font` と入れ、`bk_font.tms` を選ぶ →「既知の形式」タブ。
   フォント画像が出るので **文字の番号を重ねる** を押す (1 文字 23、1 行 17)。
6. 番号 0 から順に文字を書き出し、`.msg` 読みの「フォントの文字の並び」に貼る。
   もう一度 **.msg として読む** → 日本語になる。文字表は端末に残る。
   - 全部書き出すのが大変なら、`.msg` 読みの「使われている文字番号」を開く。
     `12=` のような雛形が並ぶので、= の後ろにフォント画像のその番号の文字を書き、
     そのまま上の欄に貼る (番号順の並びでなく **番号=文字の対応表** として読まれる)。
     フォント画像の目盛りでは、その番号が **緑の枠** になる。
     一括処理なら `python3 tools/boku2.py used ファイル…`。`font.txt` も同じ対応表の
     書き方でよい。
   - 文字表ができたら **「文字表を 16 進表示用のテーブルにする」** も押してみる。
     16 進タブで `.msg` のバイト列がそのまま日本語で見える。これが docs/01 の
     「文字テーブル」を実物で使っている状態 (一括処理なら `boku2.py table font.txt -o boku2.tbl`
     → `python3 tools/hexdump.py system.msg --table boku2.tbl`)。
7. `MAP` のファイルを 1 つ選ぶ →「既知の形式」→ **マップの入れ物を切り分ける** →
   一覧の `1.bin` を選ぶ → **.msg として読む**。`表-行` の番号で会話が並ぶ。
8. **校正用の TSV をコピー** で、その場で校正に回せる形になる。

ここまでで「読み方が合っている」ことが確かめられます。

## 2. 一括で取り出す (tools/boku2.py)

画面で確かめた読み方を、全部に適用します。文字表は `font.txt` として保存しておく
(改行はあっても無くてもよい)。

```bash
python3 tools/boku2.py unpack 実物/BOKU2.IDX 実物/BOKU2.IMG OUT/
python3 tools/boku2.py maps 実物/MAP/*.* -o OUT/maps
python3 tools/boku2.py text OUT -f font.txt -o all.tsv
```

`text` にフォルダを渡すと、中を辿って `*.msg` (深い所にあるものも) とマップの部品
`1.bin` を全部拾います。ファイルを 1 つずつ渡しても構いません。

`all.tsv` は `id / offset / size / original / translation` の 5 列。`id` は
`ファイル名:表-行` で、実機で「どのセリフか」を伝えるときの住所になります。

## 3. 校正にかける

```bash
python3 tools/boku2.py fontlist font.txt -o font_chars.txt
python3 tools/proofread.py all.tsv --font-chars font_chars.txt
```

`translation` の列を直したものを同じコマンドにかけると、フォントに無い文字・
半角・行数・用語のずれが機械的に出ます。読み方と着眼点は docs/04。

## 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 索引が「候補なし」 | `BOKU2.IDX` の先頭 4 バイトが `44 46 49 00` (DFI) か。違えば別の版 |
| 切り分けた名前が番号だけ | レコードの終わり (種別が 0/1 でなくなる行) の直後に名前が並んでいるか |
| `.msg` が「この形では読めない」 | 先頭 4 バイトが件数 (小さい数) か。入れ物なら先に切り分ける。日記の雛形や保存画面の文言は見出しの無い並び (0x8000 区切り)、保存画面の一部は Shift-JIS (0x00 区切り) で、どちらも自動で試す |
| 文字が `[123]` のまま | 文字表が貼られていない、または短い。「文字番号の最大」より長くする |
| 文字がずれて別の字になる | フォントの番号の振り方 (1 文字の幅・余白) がずれている。0 番の位置を合わせる |
| `{VOICE 00010001}` が混ざる | 音声の番号。会話ではないので TSV には入れない (`text --keep-voice` で残せる) |
| `maps` で「入れ物ではありません」 | そのファイルの先頭 16 バイトを 16 進で見る。項目数 + (位置, 長さ) の並びでなければ別形式 |

## 練習用データでの答え合わせ

`work/BOKU2SAMPLE/answer.tsv` に、取り出せるはずの全文があります。
`all.tsv` の `original` と一致すれば、手順が正しく通っています。
