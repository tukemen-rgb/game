# 僕の夏休み 2 のテキストを取り出す手順 (通し)

構造探査台と `tools/boku2.py` を使って、吸い出したフォルダから会話テキストを
校正用の TSV にするまでの、順番どおりの手順です。判明した形式の説明は
docs/09、法律面の注意は docs/05 を先に読んでください (取り出したデータや
訳文を配布することは、はっきり問題があります)。

先に **練習用データで一周** しておくと、実物で迷いません:

```bash
python3 tools/make_boku2_sample.py      # work/BOKU2SAMPLE/ に同じ形の架空データ
```

以下、`実物` と書いた所を `work/BOKU2SAMPLE` に読み替えれば、そのまま通ります
(練習用のフォント画像は模様なので、文字表は付属の `font.txt` を使います)。

用語: この文書で **文字表** と呼ぶのは、docs/01 の「文字テーブル」をフォント画像の
並び順でそのまま作ったものです (番号 = 画像の何番目の文字か)。**入れ物** は
「項目数 + 位置と長さの表」で部品をまとめたファイル、**索引** は本体とは別の
ファイルに置かれた一覧 (`BOKU2.IDX`) を指します。

## Windows で使うとき (先に一度だけ読む)

この文書のコマンドは `python3 …` と書いてありますが、Windows では `python3` が
無いことが多い (python.org の Python は `python` か `py` で呼ぶ。`python3` と打つと
Microsoft Store が開くことがある)。**`python3` を `py -3` に読み替えて**ください:

```text
py -3 tools/boku2.py check 実物\
```

そのほかは道具の側で吸収してあるので、そのまま打てば動きます:

| Windows で起きること | 道具の側の対応 |
| --- | --- |
| `*.*` をシェルが展開しない | `maps` / `text` が自分で探す。フォルダを渡してもよい |
| 区切りが `\` | `実物\MAP` のままでよい (`/` でもよい) |
| コンソールが cp932 で、無い文字があると落ちる | 無い文字は `?` にして続ける |
| メモ帳や Excel で保存した文字表・TSV に BOM が付く、UTF-16 や ANSI になる | **読む**のはどの形式でも同じ。ただし **ANSI で保存すると `¥ — ♡ ︙` が `?` に変わる** (「3. 校正にかける」参照)。文字表が潰れていれば `check` / `text` が言う |
| `all.tsv` を Excel で開くと化ける | BOM 付きで書き出すので化けない |

Python は 3.10 以降で確認しています (3.10 と 3.13 でテストを通している)。

## 実物が届いた日の最初の 1 時間

この一式が実物のデータを通ったのは**索引の切り分け 1 件だけ**です
(社長の吸い出しで 1951 個に切り分けられた。ただし当時は名前が付かず
`#0 #1 …` のままでした)。下の道具と判定はその後に作ったもので、
合成データと公開ソースだけで組み立てています。どこまで確かめてあるかの一覧は
docs/09 の「実物で確かめたこと」の表です (この手順書では持ちません。
2 か所に書くと食い違うため)。だから最初の 1 時間の目的は「全部取り出すこと」ではなく、
**どこまでが当たっていて、どこから外れるかを確定させること**です。
外れた場所さえ分かれば、次の手はほぼ決まります。

順番と、それぞれで見る 1 点だけを挙げます。

| | やること | 見る 1 点 (道具がそう出力する) | 外れたら |
| --- | --- | --- | --- |
| 〜5 分 | `boku2.py check 実物` | 最後の行に**「確認事項 N 件」が出るかどうか**。出なければ先へ進んでよい (「問題なし」のほか、「→ の行はありません。ただし**診ていない段があります**」も報告するものが無いという意味 —— **全部を診た**という意味ではない) | → の行をそのまま報告。**この先に進まない** |
| 〜8 分 | 同じ `check` の `[検査値]` の段 | 「**同じ数**です」と「件すべて合いました」の 2 つが出るか (`BOKU2.CRC` を吸い出しに入れておくこと) | **出なければ 3 通りに分かれる。道具がどれかを言うので、そのとおりにする。** (a)「合わなかった分の検査値は検査値ファイルの中に … **見つかります**」= 切り分けの位置は合っていて**並びが違うだけ**。続けて出る `--names-from-crc` を打って**先へ進んでよい**。(b)「… に固まっています」= 吸い出しがその区間で壊れている。**もう一度吸い出すと直ることがある**。(c) それ以外 = **索引の読み方が外れている**。ここから先の段は当てにならないので、その行ごと報告して**先へ進まない** |
| 〜10 分 | 同じ `check` の `[MAP]` の行 | 「N 件 / 入れ物として読めた N 件 / 1 番が会話だった N 件」の 3 つ目が 0 でないか | 0 なら入れ物の刻み (8/12 バイト) の推定が外れている |
| 〜20 分 | `boku2.py unpack` | 「N 個に切り分けました」の N (実物なら 1900 前後、練習データなら 20)。続けて `system/system.msg` のような**フォルダ付きの名前**が並ぶか | 名前が付かないなら索引の名前の置き場が違う。`check` の → にその旨が出る。**`BOKU2.CRC` があれば `--names-from-crc` で名前が付く** (手順 3)。検査値が**全部は合っていなくても**、中身の検査値から引き当てられる分は付く —— 何件付くかは `check` が先に言う |
| 〜25 分 | `boku2.py maps 実物/MAP/*.*` | 「N 個の入れ物から N 個の部品」 | 1 つも切り出せなければ道具が `→` で止まる。そのときは上の `[MAP]` の行を先に見る |
| 〜40 分 | 文字表を作る (下記) | 仮名が読める並びになるか | ここが最も手間。下書き機能を使う |
| 〜55 分 | `boku2.py text OUT -f font.txt -o all.tsv` | 「文字表で全部読めました」か「文字表に無い番号: N 種 (例: …)」 | 出た番号だけを埋めれば進む。全部そろえなくてよい。「文字表は試せていません」と出たら、渡した範囲が Shift-JIS だけで文字表を引いていない (下記) |
| 〜60 分 | `proofread.py all.tsv --font-chars <実物の文字表>` | 「使った設定」の行の文字表が**実物のもの**になっているか | 練習用の設定のままだと、別の作品の物差しで測ることになる |

表の「見る 1 点」は、**道具が実際にその言葉で出力する**ものだけにしてあります
(練習データで 1 つずつ確かめました)。出ない値を探して時間を使わないためです。

**最初の 1 時間で最も時間を食うのは文字表です。** 1656 個のマスに文字を割り当てる
作業で、手でやると数時間かかります。構造探査台の `bk_font.tms` を開いて
「**文字表の下書きを作る**」を押すと、形を突き合わせて下書きを作ります。
合成データでの実測では、形だけで 46/57、並び順の補正を入れて 53/57 でした。
下書きと一緒に「**まず疑うマス**」が 12 個出ます。点数の低い順ではなく
**1 位と 2 位の差が小さい順**です (点数は当たり外れの目安になりませんでした。
docs/11 の 10 節)。そこから目で直すのが速い道です。

この 1 時間で **やらなくていいこと** も決めておきます。

* 全文の校正。訳文がまだ無いので、原文と見比べる検査は動きません (docs/04)
* 訳文を入れ直す方法を探すこと。この一式ではやりません (下の「4. ここで終わり」)
* 下書きの文字表を完璧にすること。会話が 1 本読めれば、形式の確認としては十分

### 終わったときに報告してほしいもの

うまくいってもいかなくても、**この 3 つ**があれば次の手が決められます。

1. `boku2.py check 実物` の出力**全部** (本文は含まれません。位置と分類だけ)
2. `unpack` の件数と、`text` が出した「文字表で全部読めました」または
   足りない番号の一覧
3. 外れた所があれば、その画面の「報告用の要約」(構造探査台の索引タブ)

**推測で直さないでください。** この一式の索引・入れ物・文字表の読み方は、
公開ソースから学んだ**推定**が混ざっています (docs/09 の第 8 節)。実物で外れた
という事実そのものが、いちばん価値のある情報です。

## 0. 手元にあるもの

吸い出したフォルダ (`SYSTEM.CNF`, `SCPS_150.26`, `BOKU2.IDX`, `BOKU2.IMG`,
`MAP/`, `BGM/`, `VOICE/`)。テキストは次の 2 か所にあります。

| 場所 | 中身 | 読み方 |
| --- | --- | --- |
| `BOKU2.IMG` の中の `system/**/*.msg` | メニュー・道具・釣り・虫の名前など | 索引で切り分けてから `.msg` として読む |
| `MAP/*.*` の各ファイルの 1 番 | 物語の会話 (本体) | 入れ物を切り分けてから `.msg` として読む |

## 0.5 まず診断 (1 コマンド)

```bash
python3 tools/boku2.py check 実物/
```

索引・本体・フォント・MAP を一通り診て、**報告用の要約**を出します (ゲームの本文は
出しません)。**最後の行に「確認事項 N 件」が出なければ次へ**。
**その 1 行上に「診ていない段: N 件 (…)」が出ていたら、そこは見ていません** ——
締めもそのときは「問題なし」ではなく「**→ の行はありません。ただし診ていない段が
あります**」になります。どちらも「全部を診た結果」ではなく「診た分には問題が
無かった」という意味です。`→` の行が出たら、その出力ごと貼って報告すれば、
先頭 16 バイトなどの手がかりが含まれているので次の手が打てます。

Python を使わない場合は、構造探査台の「索引ファイル」タブで解析したあとに出る
**「報告用の要約を作る」** が同じものを出します (MAP のファイルも一緒に読み込んで
おくと MAP まで診ます)。

## 1. 画面で確かめる (構造探査台)

1. **フォルダごと読む** で吸い出したフォルダを開く。
2. 「索引ファイル」タブ → 索引 `BOKU2.IDX` / 本体 `BOKU2.IMG` → **解析する**。
   「候補 1 件 (DFI 形式として読みました)」と出れば正解。
3. **この解釈で N 個に切り分ける** を押す。一覧に `system/system.msg` のように
   フォルダ付きの名前が並ぶ。
   - `#0012.tm2` のように番号だけなら名前の読み取りに失敗している。
     **どこで外れたかは道具が指します** —— 「名前は **N 個目で止まっています**:
     位置 0x… に …」か「名前の置き場と思った所が、名前らしくありません」が出るので、
     **その行をそのまま報告**してください (自分で 16 進を探さなくてよい)。
   - **それでも名前を付けられることがある。** `BOKU2.CRC` には索引とは別に
     名前が入っていて、各ファイルの先頭 128 バイトの検査値も持っている。
     **画面は切り分けるときに自動でこれを当てます** (`BOKU2.CRC` も一緒に
     読み込んでいれば)。当てたときは「検査値ファイルの名前を N 件当てました」と
     出ます。裏が取れない項目は番号のままです。一括処理ではこう打ちます:

     ```bash
     python3 tools/boku2.py unpack 実物/BOKU2.IDX 実物/BOKU2.IMG OUT/ --names-from-crc 実物/BOKU2.CRC
     ```

     **1 件ずつ検査値で裏を取って**、合った項目にだけ名前を使います
     (フォルダは付かず、ファイル名だけになります)。合わなければ番号のままです。
     **検査値が全部合っていなくても打てます。** 当て方は 2 通りあって、
     並びが合っていればその順で、合っていなければ**中身の検査値から引き当てます**
     (同じ検査値の名前が 2 つ以上ある分は付けません)。何件付くかは `check` が
     先に言うので、その数だけ付きます。
     フォルダが付かないぶん、**別のフォルダの同じ名前がぶつかります**。
     ぶつかった分は `~2` を付けて両方残し、その件数も言います
     (黙って上書きすると、ファイルが 1 つ減ったことに誰も気づけません)。
4. 一覧の絞り込みに `msg` と入れ、`system.msg` を選ぶ →「既知の形式」タブ →
   **このファイルを .msg として読む**。件数と、各行の文字番号 `[123]` が並ぶ。
5. 絞り込みに `font` と入れ、`bk_font.tms` を選ぶ →「既知の形式」タブ。
   フォント画像が出るので **文字の番号を重ねる** を押す
   (既定のまま。**刻み 22 ドット**、実物は **1 行 23 字**。列数は画像の幅から
   自動で決まる。描かれる枠は 23 ドットで 1 ドット重なるので、**枠の 23 を刻みに
   使わないこと**)。**画面が「1 行 23 字で番号を振っています」と出れば合っています。**
   23 以外の数字が出たら、そのまま書き出すと文字表が丸ごとずれます (出てくる字は
   日本語のままなので目では気づけません)。画面が ⚠ を付けて言うので、その場で止めて
   刻みと余白の欄を戻してください。
6. 番号 0 から順に文字を書き出し、`.msg` 読みの「フォントの文字の並び」に貼る。
   もう一度 **.msg として読む** → 日本語になる。文字表は端末に残る。
   - **1 枚では終わりません。** この作品の文字表は全部で 1656 字あるのに、
     `bk_font.tms` の頁は 1058 マスしかない (512×1024 ドット)。残り 598 字は
     **別の画像**にあります。画面と `check` がマス数と足りない字数を言うので、
     書き写したあとに本文へ `[1234]` が残っても、**書き写しの間違いではありません**。
     **残りがどこにあるかは道具が探します。** `check` は吸い出し全体から、
     1 行 23 字の幅で残りが入る画像を挙げ、**1 枚目と同じ幅のものを先に**出します
     (文字表はどの頁も同じ升目なので、続きなら幅は 1 枚目と同じはず。
     英語化パッチの公開ソースに残っている 2 枚も 512×1024 と 512×640 で幅が揃っていた)。
     幅 506〜527 ドットの画像は背景や UI にもあるので、幅の違う候補も 3 件まで出しますが、
     **まず「← 1 枚目と同じ幅」が付いたものから開いてください**。
     見つからなかったときは、**どこまで見たか**が出ます (名前に `font` が付くものと
     `.tms` は先頭 4 MB まで、ほかは先頭 64 KB まで)。実物には TIM2 を
     1.5 MB 先に持つファイルがある (公開ソースの書き出しに `title.tms_0x18b780` がある)
     ので、**64 KB までしか見ていないファイルの奥に隠れている**可能性は残ります。
     画面の「既知の形式」タブは、
     同じファイルに TIM2 が 2 枚以上あれば位置の釦を出すので、そこで 2 枚目を
     選んで同じ手順を繰り返してください。**2 枚目の番号は 0 からではなく、
     1 枚目の続きから**始まります (画面がそう出ます)。0 から振り直すと
     文字表が丸ごとずれます。
     **一括処理には、頁ごとに保存したものを並べて渡せます** (#256):

     ```text
     python3 tools/boku2.py text OUT -f font1.txt -f font2.txt -o all.tsv
     python3 tools/boku2.py fontlist font1.txt font2.txt -o font_chars.txt
     ```

     この順につなぎます。何字ずつつないだかを言い、1 枚目が 1058 字でなければ
     「順番が逆かもしれません」と出します。**2 枚目だけを渡すと 1058 字ぶん
     手前にずれます** —— それでも日本語は出てしまうので、目では気づけません。
   - 手で書き写す前に **「文字表の下書きを作る」** を押すと、マスの形に似た字を当てて
     下書きを入れる。**当たりは保証しない**ので、必ず目で確かめて直す道具。
     `.msg` を先に読んでおくと、本文で要る番号だけに絞れる。仮名・数字・記号だけが
     候補なので、漢字は下の欄に貼るか手で書く。画面に **紛らわしい順** が出るので、
     そこから見ると速い。小書きの字 (っ ゃ) と大きい字、濁点・半濁点の有無、
     `0` と `O`、`。` と `゜` は形が近く、実測でもそこを間違えた。
     **カタカナと漢字の見分けも同じくらい危ない**: `ー` と `一`、`カ` と `力`、
     `ロ` と `口`、`ニ` と `二`、`エ` と `工`、`ハ` と `八`、`タ` と `夕`。
     **漢字どうしの見分けも同じ**: 英語化パッチの公開ソースには同じフォントの
     書き写しが 2 通り入っていて (`font.txt` と `font1.txt`+`font2.txt`)、
     **19 か所で食い違っています** —— `千`/`干`、`礼`/`札`、`過`/`週`、`相`/`祖`、
     `匂`/`句`、`未`/`末`、`士`/`土`、`撲`/`僕`、`鰺`/`鯵`、`斉`/`育`、
     それに全角と半角 (`Ｐ`/`P`、`２`/`2`、`～`/`~`、`　`/` `)。
     **実際にパッチを出した人でもここを間違えます。**
     英語化パッチの公開ソースに残っている取り出し結果では、買い物メニューが
     「コ一ヒ一牛乳」(漢数字の 一) になっている。**製品側の誤字か文字表の
     取り違えかは分からない**が、どちらにせよ目では気づけない。
     取り出したあと `proofread.py` にかけると `notation` で鳴る (docs/04)。
     形で当てたあと **並び順**でも直す。続いたマスが続いた字に当たっていれば、
     その区間は五十音の並びで埋め直すので、小書きや濁点の取り違えはここで消える。
     フォントが五十音順に並んでいなければ支持が集まらず、何も起きない。
     漢字は既定の候補に入っていないので、**「下書きの候補に足す字」** の欄に
     貼ってから押す (貼った字も同じように形で当てにいく)。貼る字は並べるだけでよい。
   - 全部書き出すのが大変なら、`.msg` 読みの「使われている文字番号」を開く。
     `12=` のような雛形が並ぶので、= の後ろにフォント画像のその番号の文字を書き、
     そのまま上の欄に貼る (番号順の並びでなく **番号=文字の対応表** として読まれる)。
     **ここに出るのは、いま開いているファイルの分だけです。** 練習データの
     `system.msg` では 15 種ですが、吸い出しぜんぶでは 68 種あります。
     ここだけ書き写して終わりにすると、文字表が足りないまま先へ進みます。
     本文ぜんぶで何種要るかは、下の「報告用の要約を作る」に出ます。
     フォント画像の目盛りでは、その番号が **緑の枠** になり、そのうち文字表にまだ
     無い番号は **橙の枠** になる (要約にも「文字表に無い番号 K 種」と出る)。
     緑は**読むたびに足していく**ので、前に読んだファイルの分が消えることはない。
     **先に「報告用の要約を作る」を一度押しておくと、吸い出しぜんぶの分が緑になる**
     ので、1 ファイルずつ開いて回らなくてよい (目盛りの説明文が、いま緑になっている
     のがどこまでの分かを必ず言う)。
     橙が無くなれば「文字表で全部読める」。文字表を貼ったまま「索引ファイル」タブの
     **「報告用の要約を作る」** をもう一度押すと、`[文字表] 貼ってある文字表: N 字 /
     … 文字表に無い K 種` と、**本文ぜんぶ**での出来具合が出る —— 先頭 2000 件の
     `.msg` だけでなく、入れ物 (日記・保存画面・出来事・釣り) と MAP の物語の会話も
     合わせた数です (`boku2.py check` の `[文字表]` と同じ項目。内訳も出ます)。
     一括処理なら `python3 tools/boku2.py used 取り出したフォルダ`。
     **ここはフォルダを渡してください。** ファイルを並べて渡すと、深い所の `.msg` と
     入れ物が丸ごと落ちます —— 練習データで数えたら **68 種が 15 種**になり、
     いちばん大きい番号も 165 が 87 になりました。**書き写す番号が足りないまま
     文字表ができあがる**ので、道具の側も「渡したファイルの中だけの数です」と断り、
     拾えたはずのファイルを数えて言います。`font.txt` も同じ対応表の書き方でよい。
   - 書けたら **「文字表をファイルに保存」** を押す。`font.txt` がそのまま落ちてくる。
     **メモ帳や Excel に貼り直さないこと。** あの 2 つは保存のときに
     「ANSI (cp932)」を選べてしまい、この作品の文字表にある `¥` `—` `♡` `︙` が
     その瞬間に `?` に化ける (docs/04 の「半角の `?` を、訳文のせいにしない」)。
     この釦で落ちたものは必ず UTF-8 で、そのまま
     `python3 tools/boku2.py fontlist font.txt -o font_chars.txt` に渡せる。
   - 文字表ができたら **「文字表を 16 進表示用のテーブルにする」** も押してみる。
     16 進タブで `.msg` のバイト列がそのまま日本語で見える。これが docs/01 の
     「文字テーブル」を実物で使っている状態 (一括処理なら `boku2.py table font.txt -o boku2.tbl`
     → `python3 tools/hexdump.py system.msg --table boku2.tbl`)。
7. `MAP` のファイルを 1 つ選ぶ →「既知の形式」→ **マップの入れ物を切り分ける** →
   一覧の `1.bin` を選ぶ → **.msg として読む**。`表-行` の番号で会話が並ぶ。
   部品を読んで「これはマップの入れ物です」と出たら (`fish_on_mem.bin` の 11〜16 番など)、
   その部品を選んだまま **もう一度切り分ける**。一括処理 (`text`) は自動で降りる。
8. **校正用の TSV をコピー** で、その場で校正に回せる形になる。
   貼る先を用意したくなければ **TSV をファイルに保存** を押す。`system.tsv` の
   ように選んだファイルの名前で落ちてくる。こちらも UTF-8 (Excel が読めるように
   先頭に印を付けてある。一括処理の書き出しと同じ形) なので、そのまま
   `python3 tools/proofread.py system.tsv --font-chars font_chars.txt` にかけられる。
   **Excel に貼って保存し直すと、列が崩れたり字が消えたりする**ので、
   落としたファイルを直接かけるのがいちばん安全。

ここまでで「読み方が合っている」ことが確かめられます。

## 2. 一括で取り出す (tools/boku2.py)

画面で確かめた読み方を、全部に適用します。文字表は `font.txt` として保存しておく
(改行はあっても無くてもよい。メモ帳や Excel で保存して先頭に BOM が付いても、
改行が CRLF でも同じに読む)。

```bash
python3 tools/boku2.py unpack 実物/BOKU2.IDX 実物/BOKU2.IMG OUT/
python3 tools/boku2.py maps 実物/MAP/*.* -o OUT/maps
python3 tools/boku2.py text OUT -f font.txt -o all.tsv
```

`text` にフォルダを渡すと、中を辿って `*.msg` (深い所にあるものも) とマップの部品
`1.bin` を全部拾います。ファイルを 1 つずつ渡しても構いませんが、
**並べて渡すと拾い漏れます。** 練習データで数えると、`OUT/system/*.msg` と
`OUT/maps/*/1.bin` を並べる書き方では **31 行のうち 12 行**しか出ませんでした
(深い所の `.msg` と、入れ物 4 つの中身が丸ごと落ちる)。

そこで `text` は、**出なかったものを言います**。**そのときは終了コードも 1 に
なります** —— 上の 3 行を続けて打つとき、`&&` でつないでいれば本文が落ちた所で
止まります。ごみを飛ばしただけ (`入れ物ではありません`) や、名前が番号のまま
だっただけなら 0 のままです。**出るはずのものが出ていないときだけ** 1 になります。

* 渡されたのがファイルばかりのとき、同じ場所に**渡されなかった**読めるファイルが
  あれば、その数と名前を出します。
* 読める形なのに **1 行も出なかった**ファイルがあれば、その名前を出します。

「文字表で全部読めました」は**文字表の話しかしていません**。
上の `→` の行が出ていないことも、あわせて確かめてください。

Windows のコマンドプロンプト / PowerShell でも `実物/MAP/*.*` はそのまま打って
大丈夫です (シェルは `*` を展開しませんが、道具の側で探します)。
`maps 実物/MAP -o OUT/maps` のようにフォルダを渡しても同じです。

`all.tsv` は `id / offset / size / original / translation` の 5 列。`id` は
`ファイル名:表-行` (マップの会話は `マップ名:表-行`、入れ物の部品は `入れ物名#部品:行`、
入れ物の中の入れ物は `fish_on_mem#11#2:行` のように `#` が重なる) で、
実機で「どのセリフか」を伝えるときの住所になります。

## 3. 校正にかける

```bash
python3 tools/boku2.py fontlist font.txt -o font_chars.txt
python3 tools/proofread.py all.tsv --font-chars font_chars.txt
```

`translation` の列を直したものを同じコマンドにかけると、フォントに無い文字・
半角・行数・用語のずれが機械的に出ます。読み方と着眼点は docs/04。

### `id` と `size` の欄は消さないでください

この 2 列は、**入れ直す先の住所** (`id`) と **入れ物の大きさ** (`size`) であると
同時に、**表計算での事故を見つけるための控え**です。訳文だけを見ていては
絶対に分からない事故が 4 つあり、どれもこの 2 列があって初めて見つかります。

| 起きる事故 | どうなるか | 道具の言い方 | 要る欄 |
| --- | --- | --- | --- |
| 行を挿入・削除して訳し始めた | 以降の訳文が**全部 1 行ずれる** | 「訳文が 1 行ずれている疑い」 | `original` の並び |
| 行を複製した | 入れ直す段で**片方が黙って消える** | 「同じ id の行が N 種あります」 | `id` |
| id の欄を消した | **どのセリフか分からない** | 「id の欄が空の行が N 行あります」 | `id` |
| 列を並べ替えて保存した | **訳文が消えて原文が戻る** | 「原文と訳文の欄が入れ替わっている疑い」 | `size` |
| 訳文が元の場所に入らない | 入れ直す段で詰まる | 「原文の入れ物」 | `size` |

**4 つとも、1 行ずつ見ている限り何も鳴りません。** 列の並べ替えに至っては、
練習データで試すと「ERROR 0 件 / WARN 0 件 / 問題なし」で満点が出ました。
読み方は docs/04 の「1 行ずれ」「id は触らない」「列を入れ替えない」
「入れ物の大きさ」。

欄を消しても道具は動きますが、**消した分の検査は黙って止まります**
(`size` が無ければ「入るかどうかの検査は動いていません」と出ます)。
Excel で並べ替えるときは**表全体**を選んでから並べ替えてください。

**指摘が多いときは、画面には最初の 20 行だけ出ます。** 実物は 1 万行を超える
見込みで、最初の 1 回は指摘が数千件出ます。全部を画面に流すと、いちばん大事な
「N 行をチェック」の行と、**原因を名指しする注意**がその下に埋もれてしまうので、
残りは数と内訳で言うようにしてあります。全部見るときは TSV に書き出して、
表計算で並べ替えたり絞り込んだりしてください:

```bash
python3 tools/proofread.py all.tsv --font-chars font_chars.txt --report 指摘.tsv
```

`all.tsv` は Excel でそのまま開けます (BOM 付き UTF-8 なので日本語が化けない)。
Excel で直して保存し直すときは「Unicode テキスト (*.txt)」でも「CSV UTF-8」でも
構いません。**読む**のはどの形式でも道具の側が見分けます。

**ただし「ANSI」(cp932) だけは使わないでください。** 読めないのではなく、
**保存するときに字が消えます。** この作品のフォントには cp932 で書けない字が
4 つあり (`¥` `—` `♡` `︙`)、ANSI で保存するとその場で `?` に変わります。
`♡` は台詞に普通に出るので、**本文がその場で書き換わったまま先へ進む**ことに
なります。しかも `?` は半角なので、校正では「半角文字が混ざっています」と出て、
**訳文のせいに見えます**。文字表 (`font.txt`) も同じです。
`check` と `text` は、文字表に `?` が 2 つ以上あればその旨を言います
(本物の `?` はフォントに 1 つだけです)。

**改行はフォント画像の 1 行ずつで入れてください。** 文字表は画像を左上から
1 行 23 字ずつ書き写して作りますが、どこか 1 行だけ 22 字や 24 字になると、
**その行から下の番号が全部ずれます**。ずれても全部の番号に字は当たるので、
取り出した本文は日本語のまま出てきて、`text` も「文字表で全部読めました」と
言います。**目でも道具でも気づけない**——唯一の手がかりが、書き写したときの
行の幅です。`check` / `text` / `fontlist` と画面の「font.txt に保存」は、
行の幅が揃っていなければ**何行目か**と**何番から下がずれるか**を言います
(改行を入れずに 1 行に流し込むと、この見張りは効きません)。

### 実物の枠の仕様が分かったら (直すのは 1 か所)

`proofread.py` の `line_width` と `line_count` は、**練習用の作品の数字**
(1 行 18 文字 / 1 ページ 3 行) で測っています。この作品の枠の仕様は
分かっていないので、いまの指摘は「参考」です (道具も毎回そう断ります)。

いま分かっていることと、分かっていないことを分けておきます。

| 何 | 分かっているか | 根拠 |
| --- | --- | --- |
| 文字の升目 | 1 マス **22 ドット**刻みで並び、描くのは **23 ドット**四方 | 公開ソースの ASM メモ (`x right = curr_x + 0x17`)。1 ドット重なる |
| 行送り | **26 ドット** | 同じメモ (`y top = base_y + (newlines*0x1A)`) |
| 折り返し | **原稿の側に改行が入っている** (`0x8001`)。ゲームが自動で折らない | `.msg` の中身そのもの |
| 1 行に入る文字数 | **分かっていない** | 枠の内側の幅 (ドット) が要る |
| 1 ページの行数 | **分かっていない** | 枠の内側の高さ (ドット) が要る |

原稿に改行が入っているので、**原文の実測がそのまま下限**になります。公開ソースに
残っている実物の日本語を測ると、いちばん長い行で **13.5 文字分**でした
(`proofread.py` は毎回「原文の 1 行の幅: 最大 N」を出すので、手元の取り出しでも
同じことが確かめられます)。

枠の内側のドット数が分かったら、**入る文字数は割り算で出ます**。

| 分かった数 | 入れる値 |
| --- | --- |
| 枠の内側の幅 (ドット) | 幅 ÷ 22 → `line_max_width` |
| 枠の内側の高さ (ドット) | 高さ ÷ 26 → `lines_max` |
| プレイヤー名などの最大の長さ | そのまま `var_width` |

**直す所は `data/rules.json` の 1 か所です。**

```bash
python3 tools/proofread.py all.tsv --line-width 13.5 --lines-max 4
```

上のように `--line-width` / `--lines-max` で**試してから**、決まった数字を
`data/rules.json` の `ja` に書きます。検査台 (`make_viewer.py`) も同じ
`data/rules.json` を読むので、書き換えれば画面の「枠の上限」の線も一緒に動きます。

## 4. ここで終わり (この先が無い理由)

**この一式の道は、校正した TSV で終わります。** 実物のゲームに訳文を入れ直す手順は
用意していません。道具が足りないのではなく、**そうしない**という決めです。

| よくある思い込み | 実際 |
| --- | --- |
| 手順 3 のあとに「入れ直す」があるはず | ありません。僕の夏休み 2 の側は読むだけです |
| `insert_text.py` が使えるはず | あれは docs/01〜03 の**自作の練習データ** (SCRP 形式) 用です。`all.tsv` を渡すと、そう言って止まります |
| 訳文を配れば誰かが入れてくれる | 取り出したデータも訳文も、配ると権利の問題がはっきり出ます (docs/05) |

学ぶ目的から見ると、ここまでで一周しています。**どこに文言があるかを突き止め、
読める形にし、機械で検査できる形に整える**、が抽出とローカライズ QA の中身だからです。
入れ直しの手つきは、権利の心配がまったく無い自作データ (docs/01〜03、手順 7) で
同じことを一通りやれます。ポインタの振り直しも容量の制約も、そちらで体験できます。

やり切ったかどうかは、次で確かめられます。

- `check` が「問題なし」で終わる
- `[文字表] … 文字表に無い 0 種` になる (`.msg` の範囲が全部読める)
- `proofread.py` が ERROR 0 件になる

この 3 つは **中身があるときだけ** 成り立ちます。空の TSV や 0 字の文字表を渡すと、
道具は「0 件」ではなく「1 行もありません」「0 字です」と言って止まります
(何も検査していないものを合格にしないため)。

## 報告するとき (何を貼れば次の手が打てるか)

本文 (ゲームのセリフ) は貼らなくてよい。次の 3 つで十分です。

1. `python3 tools/boku2.py check 実物/` の出力全部 (または画面の「報告用の要約」)。
   とくに次の行が決め手になる:
   - `[索引]` の `DFI: 期待どおり` と `名前が付いた N 件`
   - `[検査値] BOKU2.CRC: 項目 N 件 / 名前 N 件 / 検査値 N 個` と、その下の 2 行
     (`索引から数えたファイル N 件と**同じ数**です` / `切り分けた先頭 128 バイトの検査値: N 件すべて合いました`)。
     **索引とは別の所から出る裏付けなので、いまはここがいちばん強い決め手**です。
     `BOKU2.CRC` を吸い出しに入れ忘れると「BOKU2.CRC は無い」と出て、この決め手が丸ごと欠けます
   - `フォルダの規則: 2 通り (stack / flag) で一致 (フォルダの中のファイル N 件で突き合わせた)`
     (食い違いが出たらその行ごと。N が分母。入れ子の無い索引では 2 通りに差が出ないので、
     そのときは「試せていない」と出る — この規則はまだ実物で確かめていない)
   - `[フォント] … N×M ドット / 1 画素 …` (幅は最低 506 ドット要る。
     実物は 512 の見込み。足りなければ `→` が出る)
   - `[文字表] font.txt: N 字 / … 文字表に無い K 種` (文字表を作り始めたら `font.txt` を
     同じフォルダに置く。K が 0 になれば `.msg` の範囲は全部読める。画面では
     「.msg として読む」の欄に貼ってある文字表で同じ行が出る)
   - `位置表の長さの欄: 合う N 件 / 合わない M 件` (8 バイト刻みの後ろ 4 バイトが
     その項目のバイト長か。合わない件数が出たらその行ごと)
   - `[MAP] … 1 番が会話だった N 件 / 会話 M 行`
2. `.msg として読む` を `system.msg` で押したときの要約 1 行
   (`N 件 … · 本文あり … · 文字番号の最大 …`)。
3. 何かが `→` で出たら、その行に付いている先頭 16 バイトや 64 バイト。

これだけで、索引・本体・フォント・入れ物・会話の 5 段のどこで外れたかが分かります。

## 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 索引が「候補なし」 | `BOKU2.IDX` の先頭 4 バイトが `44 46 49 00` (DFI) か。違えば別の版 |
| 切り分けた名前が番号だけ | レコードの終わり (種別が 0/1 でなくなる行) の直後に名前が並んでいるか |
| `.msg` が「この形では読めませんでした」 | 先頭 4 バイトが件数 (小さい数) か。入れ物なら先に切り分ける。日記の雛形や保存画面の文言は見出しの無い並び (0x8000 区切り)、保存画面の一部は Shift-JIS (0x00 区切り) で、どちらも自動で試す |
| 文字が `[123]` のまま | 文字表が貼られていない、または短い。「文字番号の最大」より長くする。`text` は終わりに「文字表に無い番号: N 種 (例: …)」と出すので、その番号の文字を足す |
| `check` が「索引と本体が揃っていません」 | 指定したフォルダが ISO のまま (先に展開)、または一段上 (中のフォルダを指定)。どちらも `check` が次の行で教える |
| 文字がずれて別の字になる | フォントの番号の振り方 (1 文字の幅・余白) がずれている。0 番の位置を合わせる |
| `{VOICE 00010001}` が混ざる | 音声の番号。会話ではないので TSV には入れない (`text --keep-voice` で残せる) |
| `maps` で「入れ物ではありません」 | そのファイルは**飛ばして**、残りは切り分けます。名前に覚えがなければ `.DS_Store` (Mac) や `Thumbs.db` (Windows) の置き土産なので、そのままで構いません。MAP のファイルのつもりなら、先頭 16 バイトを 16 進で見る。項目数 + (位置, 長さ) の並びでなければ別形式 |
| `--names-from-crc` で「をこの形で読めないので、名前は索引のものを使います」 | `BOKU2.CRC` が見出しの形と合わない (版が違う疑い)。名前は索引のものになるので、番号だけのままなら `check` の出力ごと報告してください |
| `--names-from-crc` で「そのうち N 件は名前がぶつかったので `~2` を付けました」 | 検査値ファイルの名前には**フォルダが付かない**ので、別のフォルダの同じ名前が重なった。`~2` を付けて**両方残して**あるので、ファイルは 1 つも減っていない。索引の名前が読めるようになれば、フォルダ付きの名前に戻る |
| `--names-from-crc` で「検査値ファイルの名前は 1 件も当たりませんでした」 | 検査値ファイルの名前の**並び順が索引と違う**。裏が取れないので名前は使いません (当てずっぽうで付けない)。`check` の `[検査値]` の行ごと報告してください |
| `unpack` が「名前が付かなかったファイル」と件数を言う | 索引の**名前の置き場**の読み取りが外れている。一覧が `#0012.tm2` のような番号だけになるので、`check` の出力ごと報告してください |
| `maps` が「入れ物が 1 つも見つかりませんでした」と言う | **続く行が原因を 2 通りに分けて言う**。(a)「指定した場所に MAP のファイルがありません」= フォルダ名違いか、まだ展開していない。打つべきコマンドが出る。(b)「ファイルは N 個ありましたが、どれも入れ物として読めませんでした」= ファイルはあった。場所違いか、**入れ物の読み方 (先頭 u32 + 位置と長さの対) がこの作品では違う**。飛ばしたファイルの名前が出るので、`check` の `[MAP]` の行ごと報告する |
| `maps` が「部品が 1 つも取り出せませんでした (入れ物として読めたファイルは N 個あります)」と言う | 入れ物の形は読めたのに、中の部品が**全部 長さ 0**。吸い出しが途中で切れているか、位置と長さの読み方が違う。**「入れ物が見つかりません」とは別物** (入れ物は読めている)。`check` の `[MAP]` の行ごと報告する |
| `text` や画面が「文字表は試せていません」と言う | その範囲が Shift-JIS だけで、文字番号を 1 つも使っていない (保存画面の一部がこれ)。文字表の出来具合はここでは分からないので、`.msg` を含む範囲でもう一度かける。**「全部読めました」とは言わない**ので、仕上がったと取り違える心配はない |
| `proofread.py` が「検査する行が 1 行もありません」と言う | 渡した TSV が見出しだけ。画面の「校正用の TSV をコピー」を貼り忘れたか、書き出しが空。**0 行を「ERROR 0 件」とは言わない**ので、合格と取り違える心配はない |
| `proofread.py` が「文字表 … が 0 字です」と言う | 渡した文字表が空。そのまま通すとフォント検査 (実機で □ になる字) だけが黙って止まるので、断っている。文字表を作ってから渡すか、他の検査だけ見たいなら `--no-font-check` |
| `compare_tsv.py` が「突き合わせた行が 1 行もありません」と言う | 両方の TSV が空か、`--ignore` で全部除いた。**0 行を「全部一致」とは言わない** |
| `text` が「文言が 1 行も見つかりませんでした」と言う | **続く行が原因を 3 通りに分けて言う**ので、その通りにする。(a)「指定した場所に読めるファイルがありません」= まだ `unpack` / `maps` を回していないか場所違い。(b)「N 個の名前が番号だけ」= 切り分けは合っているが索引の名前が読めていない。**`--names-from-crc` で切り分け直す** (手順 3)。(c)「場所が違うかもしれません」= そのフォルダに `.msg` も入れ物も無い |
| 練習用の道具 (`dump_text.py` など) が「SCRP ファイルではありません」と言う | 道具の取り違え。続く行で **見えている形式と使うべき道具** を言うので、そちらへ。索引なら `boku2.py unpack`、`.msg` なら `boku2.py text`、入れ物なら `boku2.py maps`、画像なら構造探査台の「既知の形式」 |
| `insert_text.py` が「この TSV は僕の夏休み 2 の取り出し (…) の形です」と言う | 道具の取り違え。`insert_text.py` は docs/01〜03 の**練習用 SCRP** に入れ直すためのもの。実物への書き戻しはこの一式では行わない (読み取り専用。docs/05)。`all.tsv` は `proofread.py` にかける |
| `unpack` が「同じ名前が N 件あり `~2` を付けて区別しました」と言う | 別フォルダの同名ファイルが衝突した (フォルダの入れ子の復元が外れている疑い)。**ファイルは全部出ている**ので先へ進めるが、`check` の出力ごと報告してほしい |
| `unpack` が「ファイル名に使えない字があった N 個を `_` にしました」と言う | 索引の名前に `:` `?` `*` などが入っていた。Windows では作れないので `_` に変えている。**索引に出ている名前と手元のファイル名が違う**ので、突き合わせるときは変える前の名前を見る (その行に前後が出る) |
| `unpack` が「N 個は `_` にしたら別のファイルと同じ名前になったので `~2` を付けました」と言う | 索引では違う名前 (`a:b.bin` と `a_b.bin`) でも、使えない字を `_` にすると手元では同じ名前になる。**後の 1 件で前の 1 件を上書きしない**ように `~2` を付けてある。ファイルは 1 つも減っていないので先へ進める。どちらが元のどれかは、その行の `→` で引く |
| `unpack` が「N 個はフォルダと同じ名前だったので `~2` を付けました」と言う | 索引が同じ名前 (`sys`) をフォルダにもファイルにも使っている。そのままだとフォルダが作れずに**途中で止まる**ので、ファイルの方に `~2` を付けてある。フォルダの入れ子の復元が外れている疑いもあるので、`check` の出力ごと報告してほしい |
| `proofread.py` が「この TSV は **ANSI (cp932) で保存**されています」と言う | 保存の仕方で字が消えている。cp932 に無い字 (`¥` `—` `♡` `︙`) は保存した瞬間に `?` になる。**訳文の書き方の問題ではない。** Excel は「CSV UTF-8」、メモ帳は「UTF-8」で保存し直す (docs/04 の「半角の `?` を、訳文のせいにしない」) |
| `proofread.py` が「N 行で、原文にある字が訳文では `?` になっています」と言う | 上と同じ。訳文だけを別の所から貼ったときにこちらが出る |
| `proofread.py` が「N 行の原文が、`[21]` のような**文字番号のまま**です」と言う | 文字表を付けずに取り出した TSV。`python3 tools/boku2.py text OUT -f font.txt -o all.tsv` で取り出し直す。このままではどの検査も日本語として見ていない |
| `proofread.py` が「**原文と訳文の欄が入れ替わっている疑い**があります」と言う | 表計算で列を並べ替えて保存した疑い。`size` の欄 (取り出したときの原文の大きさ) に合うのが**訳文の側ばかり**だとこう言う。**このまま入れ直すと訳文が消えて原文が戻ります**。取り出した TSV と 1 行だけ見比べて、列を戻す |
| `proofread.py` が「同じ id の行が N 種あります」と言う | 表計算で行を**複製した**疑い。取り出したままなら id は全部違う。このまま入れ直すと**どちらか片方が黙って消える**ので、複製した行を消すか id を直す。`compare_tsv.py` は同じ状態を**断って止まる** (id で突き合わせる道具なので) |
| `proofread.py` が「id の欄が空の行が N 行あります」と言う | id を消したか、行を足した。**どのセリフか分からない行**なので入れ直す先が決まらない。取り出した TSV と並べて id を戻す |
| `proofread.py` が「**訳文が 1 行ずれている疑い**があります」と言う | 訳文が**隣の行の原文**と同じ行がたくさんある。表計算で行を挿入・削除したまま訳し始めると起きる。**1 行ずつ見ても分かりません** (どの行も『訳した結果』に見えるため)。id の欄を頼りに、取り出したままの TSV と並べて確かめる。ずれたまま進めると全行やり直しになる |
| `proofread.py` が「「フォントに無い文字」が N 行」と言う | その字が実機で □ になる。**文字表を渡していないなら、訳文ではなく文字表のせい** (その場合は続く行がそう言う)。docs/04 の「機械で落とせるものは機械で落とす」 |
| `proofread.py` が「N 行のうち M 行が行数オーバーです。上限は 1 ページ K 行ですが…」と言う | **枠は 1 種類ではありません** (会話の枠と日記の頁で入る行数が違う)。半分以上が引っかかるなら、別の枠の文を混ぜている疑い。`--lines-max` を変えて別々に見る (docs/10 の「実物の枠の仕様が分かったら」) |
| `proofread.py` が「N 行すべて訳文の欄が原文と同じです」と言う | 取り出したばかりの TSV。**原文と見比べる検査は何も動いていません** (docs/04 の「動いていない検査に気づく」)。訳文を入れてからかけ直す |
| `proofread.py` が「N 行は訳文の欄が原文のままです」と言う | 上と同じことが一部の行で起きている。その行では原文と見比べる検査が働かない |
| `proofread.py` が「N 行は入れ物の大きさが数えられませんでした」と言う | その行の `size` の欄が空か、この作品の数え方 (本文の 2 バイト符号 / 保存画面の Shift-JIS) のどちらにも合わない。**その行では「入るかどうか」を見ていません**。`text` で取り出し直した TSV ならここは出ないはずなので、Excel で列を入れ替えたり `size` を書き換えたりしていないか確かめる (docs/04 の「入れ物の大きさ」) |
| `proofread.py` が「N 行の原文に、**文字表が届いていない番号**が残っています」と言う | 文字表がその番号まで作れていない。この作品の文字表は 1 枚の画像では足りない (「1. 画面で確かめる」の 6)。続きの画像から作った分も足す |
| 「一致するファイルがありません」 | `*.*` の前のフォルダ名が違う (実物/MAP など、吸い出した場所に合わせる)。フォルダをそのまま渡してもよい |

### 診断の `→` の行の読み方

**`→` で始まる行は、どの道具のものでもこの表で引けます。** `check` だけでなく
`unpack` / `maps` / `text` / `used`、それに `proofread` / `compare_tsv` が出す `→` も
入っています (画面の「報告用の要約」も同じ言い回し)。全部で 42 種類。上から順に
入口 → 索引 → 本体 → `.msg` → 入れ物 (MAP) → フォント → 本文 → 会話 → 文字表 → 校正
の段に並べてあります。課題 9 の 6 通りの壊し方で、索引・`.msg`・フォント・入れ物の
段は手元で再現できます。

| `→` の行 | どの段 | 意味と次の手 |
| --- | --- | --- |
| 索引と本体が揃っていません | 入口 | 指定したフォルダに `BOKU2.IDX` / `BOKU2.IMG` が無い。ISO のままか一段上 (次の行で教える)。**ここで止まる**ので、その先 (本体・`.msg`・フォント・MAP) は診ていない |
| 先頭が DFI でないので、この道具の索引の読みは使えません | 索引 | 先頭 4 バイトが `44 46 49 00` でない。別の版か、ファイルの取り違え。添えた 64 バイトを報告。**ここで止まる** (この先は索引が読めることが前提)。画面でも同じ要約が作れる |
| 名前の置き場が … です | 索引 | 実物なみ (レコード 1000 件以上) の索引でだけ出る。英語化パッチの公開ソースは実物の名前の置き場を **0x8140** と決め打ちしているので、そこからずれていれば**レコードの読み方 (見出し 16 バイト + 16 バイト刻み) が外れている**疑い。ずれの大きさが何件ぶんかも出る。合っていれば `→` ではなく裏付けの 1 行が出る。**`BOKU2.CRC` の検査値が全部合っていれば、この `→` は出ない** —— 0x8140 は向こうが実物の 1 枚で決め打ちした値なので、枚数が違えばずれて当たり前。証拠の強さの順は docs/09 の「証拠の強さの順」 |
| 名前が付かないファイルが多い | 索引 | レコードの直後に名前が並んでいない。**どこを見ればよいかは、この行の次の 1 行が指します** —— 「名前は **N 個目で止まっています**: 位置 0x… に …」なら**その位置**の前後 64 バイト、「名前の置き場と思った所が、名前らしくありません」なら**名前の置き場の先頭**から 64 バイト。次の行が無いときだけ、添えた 64 バイト (名前の置き場の先頭) を報告 |
| 名前が付かなかったファイル N 個 | 索引 | `unpack` が付ける。上の行と同じ原因を、切り分けたあとの数で言ったもの。一覧が `#0012` のような番号だけになる。`check` の出力ごと報告。**`BOKU2.CRC` の検査値が全部合っているなら `--names-from-crc` で名前を付けられる** (手順 3) |
| フォルダの閉じ方が合いません: … 回、もう上のフォルダが無いのに戻ろうとしました | 索引 | **入れ子の復元が外れている。** 英語化パッチの公開ソースはここで「索引が壊れている」として止まる。こちらは止めずに読み進めるが、**そのあとのファイルは根の直下に並ぶので道筋が静かにずれる** (`system/system.msg` が `system.msg` になる、など)。フォルダの閉じ方は docs/09 の表で「実物ではまだ」の行なので、ここがいちばん外れやすい。**この行ごと報告** |
| 同じ名前があります | 索引 | フォルダの入れ子の復元が外れて、別フォルダの同名ファイルが衝突した。`~2` を付けて残してある |
| フォルダの規則が 2 通りで食い違うファイル N 件 | 索引 | こちらの規則と公開ソースの規則で道筋が違う。どちらが正しいかは実物でしか決まらない。その行ごと報告 |
| 索引は N 個のファイルを名乗っていますが、取り出せるのは M 個です | 索引 | 索引の項目が**本体の外**を指している。いちばんありそうなのは **吸い出しが途中で切れている**こと (`BOKU2.IMG` の大きさを確かめる)。位置の単位の読み違いでも同じ見え方になるので、その行ごと報告 |
| 本体の中身がほとんど空です | 本体 | 索引は読めているのに、中身がゼロ埋めばかり (散らばった 30 個を覗いて数えた)。**吸い出しが途中で切れたか、コピーが終わっていない**疑い。ファイルの大きさとコピー元の残り容量を確かめる。**この先の段 (.msg・入れ物・フォント) の判定は当てにならない**。この行が出たときは、検査値・`.msg`・フォントの「読めません」は `→` ではなく**字下げの行**で出て、「上の『本体の中身がほとんど空です』から来ています」と添える —— **直すのはこの 1 つだけ**で、締めの「確認事項 N 件」もそう数える |
| 索引が本体の N% しか指していません | 本体 | 索引が本体をほとんど使っていない。レコードの長さや位置の単位 (バイト / セクタ) の読みが外れている疑い。読み方が合っていれば普通は 5 割を超える。**ただし `BOKU2.CRC` の検査値が全部合っていれば、切り分けは正しい** —— そのときは道具が「ただし**ゲーム自身の検査値は全部合っています**」と続け、下の段も今までどおり出す (本体に索引の指していない所が多いだけ)。そう続かなかったときだけ、以下が当てはまる。添えた 64 バイトを報告。**この行が出たら、検査値・`.msg`・入れ物・フォントの段は当てにならない** —— そこの「読めません」は `→` ではなく字下げの行で出て、「上の『索引が本体の N% しか指していません』から来ています」と添える。**直すのはこの 1 つだけ**。とくに**吸い出し直しでは直らない** (ディスクは無事で、読み方のほうが違う) |
| 読めない .msg の例: … 先頭 16 バイト … | `.msg` | 「件数 + 位置表」の形になっていない。入れ物なら先に切り分ける。16 バイトを報告 |
| 文言の入れ物が 1 つも読めません | 入れ物 | 日記・保存画面・出来事・釣りの文言が入った `diary.bin` / `saveload.bin` / `on_mem_event.bin` / `fish_on_mem.bin` が、どれも「先頭の項目数 + 8/12 バイト刻みの位置表」として読めない。**この分の文言が丸ごと落ちる**。`.msg` と MAP が読めているなら、外れているのは入れ物の読み方のほう。その行ごと報告 |
| 位置表の長さの欄が N 件合いません | `.msg` | 8 バイト刻みの後ろ 4 バイトがその項目のバイト長、という読みがこの作品では違うかもしれない。位置だけで読み進めてはいるので、取り出し自体は進む。その行ごと報告 |
| 入れ物が 1 つも見つかりませんでした (見たファイル N 個) | 入れ物 (MAP) | `maps` が付ける。**0 個を「0 個の部品」で通さない**ための行。続く行が原因を 2 通りに分ける —— 場所に MAP のファイルが無い / ファイルはあったが入れ物として読めない (飛ばしたファイルの名前が出る) |
| 部品が 1 つも取り出せませんでした (入れ物として読めたファイルは N 個あります) | 入れ物 (MAP) | `maps` が付ける。入れ物の形は読めたのに、中の部品が全部 長さ 0。吸い出しが途中で切れているか、位置と長さの読み方が違う。`check` の `[MAP]` の行ごと報告 |
| 入れ物として読めないファイルの例 | 入れ物 (MAP) | 「項目数 + (位置, 長さ)」の並びでない。名前と 16 バイトを報告 |
| 入れ物ではありません (飛ばしました): N 個 … | 入れ物 (MAP) | `maps` が付ける。**飛ばしただけで残りは切り分けている**ので、仕事は済んでいる。`.DS_Store` や `Thumbs.db` なら放っておいてよい。MAP のファイルのつもりなら、その名前ごと報告 |
| 入れ物としては読めましたが、1 番が会話として読めたファイルが 0 件です | 入れ物 (MAP) | 入れ物は開けたが、その 1 番の部品が「表の数 + 12 バイトの項目」になっていない。会話ファイルの読み方が外れている。添えた 16 バイトを報告 |
| [フォント] フォント画像が見つかりません | フォント | 名前に `font` が付いたファイルも、1 行 23 字の幅の画像も無かった。**吸い出しにフォントが入っていない**か、この作品の並べ方が違う。その行ごと報告 |
| [フォント] … は TIM2 として読めません | フォント | `0x80` の位置に `TIM2` が無い。前置きの長さが違うか、圧縮。16 バイトを報告 |
| [フォント] 幅が N ドットで … M ドットに足りません | フォント | 1 行 23 字を 22 ドット刻みで並べるだけの幅が無い。文字の並びの読み方 (1 行の字数・刻み) がこの作品では違う疑い。その行ごと報告 |
| [フォント] 幅が N ドットあり、… 割ると 1 行 M 字になります | フォント | 逆に**広すぎる**。幅から列数を決める「文字の番号を重ねる」が 1 行 23 字からずれ、目盛りが全部ずれる。画像の取り違えか、この作品の 1 行の字数が違う。その行ごと報告 |
| 本文の入っていそうなファイルが 1 つも見つかりません | 本文 | 名前 (`.msg` や `diary.bin` など) でも、中身の形でも見つからなかった。**吸い出しが途中で切れている**か、この作品の並べ方が違う。その行ごと報告 |
| 文言が 1 行も見つかりませんでした (見たファイル N 個) | 本文 | `text` が付ける。続く行が原因を 3 通りに分ける —— 場所にファイルが無い / 名前が番号だけ (`--names-from-crc` で切り分け直す) / `.msg` も入れ物も無い場所。**「先に `unpack` を回せ」は 1 つ目のときだけ**言う |
| 読めるはずの形なのに 1 行も出なかったファイル N 個 | 本文 | `text` が付ける。`.msg` や入れ物の形はしているのに文が 1 行も取れなかった。**本文が落ちている**ので `text` は終了コード 1 を返す。「件数 0」と自分で書いてあるファイルだけなら 0 のまま。その名前ごと報告 |
| 同じ場所に、**渡されなかった**読めるファイルが N 個 | 本文 | `text` と `used` が付ける。ファイルを 1 つずつ並べて渡したので、隣の読めるファイルが漏れている。**フォルダごと渡す**と全部拾う |
| MAP が無いので、物語の会話は 1 つも診ていません | 会話 | `MAP/` が見つからない (一括処理は指定フォルダの下 2 段まで探す) か、画面に MAP のファイルを渡していない。**診断の半分が欠けている**ので、吸い出したフォルダを指定し直すか、MAP の場所ごと報告 |
| 使われている文字番号が 1 つも見つかりませんでした | 文字表 | `used` が付ける。続く行は `text` とまったく同じ言葉で原因を分ける (場所にファイルが無い / 名前が番号だけ / 場所違い)。ファイルは拾えたのに読めなかったなら `check` で診る |
