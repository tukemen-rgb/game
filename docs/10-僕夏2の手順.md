# 僕の夏休み 2 のテキストを取り出す手順 (通し)

構造探査台と `tools/boku2.py` を使って、吸い出したフォルダから会話テキストを
校正用の TSV にするまでの、順番どおりの手順です。判明した形式の説明は
docs/09、法律面の注意は docs/05 を先に読んでください (取り出したデータや
訳文を配布することは、はっきり問題があります)。

先に **練習用データで一周** しておくと、実物で迷いません:

```bash
python3 tools/make_boku2_sample.py      # work/BOKU2SAMPLE/ に同じ形の架空データ
```

以下、`実物` と書いた所を `work/BOKU2SAMPLE` に読み替えれば、そのまま通ります
(練習用のフォント画像は模様なので、文字表は付属の `font.txt` を使います)。

用語: この文書で **文字表** と呼ぶのは、docs/01 の「文字テーブル」をフォント画像の
並び順でそのまま作ったものです (番号 = 画像の何番目の文字か)。**入れ物** は
「項目数 + 位置と長さの表」で部品をまとめたファイル、**索引** は本体とは別の
ファイルに置かれた一覧 (`BOKU2.IDX`) を指します。

## Windows で使うとき (先に一度だけ読む)

この文書のコマンドは `python3 …` と書いてありますが、Windows では `python3` が
無いことが多い (python.org の Python は `python` か `py` で呼ぶ。`python3` と打つと
Microsoft Store が開くことがある)。**`python3` を `py -3` に読み替えて**ください:

```text
py -3 tools/boku2.py check 実物\
```

そのほかは道具の側で吸収してあるので、そのまま打てば動きます:

| Windows で起きること | 道具の側の対応 |
| --- | --- |
| `*.*` をシェルが展開しない | `maps` / `text` が自分で探す。フォルダを渡してもよい |
| 区切りが `\` | `実物\MAP` のままでよい (`/` でもよい) |
| コンソールが cp932 で、無い文字があると落ちる | 無い文字は `?` にして続ける |
| メモ帳や Excel で保存した文字表・TSV に BOM が付く、UTF-16 や ANSI になる | どの形式でも同じに読む |
| `all.tsv` を Excel で開くと化ける | BOM 付きで書き出すので化けない |

Python は 3.10 以降で確認しています (3.10 と 3.13 でテストを通している)。

## 0. 手元にあるもの

吸い出したフォルダ (`SYSTEM.CNF`, `SCPS_150.26`, `BOKU2.IDX`, `BOKU2.IMG`,
`MAP/`, `BGM/`, `VOICE/`)。テキストは次の 2 か所にあります。

| 場所 | 中身 | 読み方 |
| --- | --- | --- |
| `BOKU2.IMG` の中の `system/**/*.msg` | メニュー・道具・釣り・虫の名前など | 索引で切り分けてから `.msg` として読む |
| `MAP/*.*` の各ファイルの 1 番 | 物語の会話 (本体) | 入れ物を切り分けてから `.msg` として読む |

## 0.5 まず診断 (1 コマンド)

```bash
python3 tools/boku2.py check 実物/
```

索引・本体・フォント・MAP を一通り診て、**報告用の要約**を出します (ゲームの本文は
出しません)。「問題なし」なら次へ。`→` の行が出たら、その出力ごと貼って報告すれば、
先頭 16 バイトなどの手がかりが含まれているので次の手が打てます。

Python を使わない場合は、構造探査台の「索引ファイル」タブで解析したあとに出る
**「報告用の要約を作る」** が同じものを出します (MAP のファイルも一緒に読み込んで
おくと MAP まで診ます)。

## 1. 画面で確かめる (構造探査台)

1. **フォルダごと読む** で吸い出したフォルダを開く。
2. 「索引ファイル」タブ → 索引 `BOKU2.IDX` / 本体 `BOKU2.IMG` → **解析する**。
   「候補 1 件 (DFI 形式として読みました)」と出れば正解。
3. **この解釈で N 個に切り分ける** を押す。一覧に `system/system.msg` のように
   フォルダ付きの名前が並ぶ。
   - `#0012.tm2` のように番号だけなら名前の読み取りに失敗している。
     `BOKU2.IDX` の 16 進表示で、レコードの終わり (0x8140 付近) を見て報告する。
4. 一覧の絞り込みに `msg` と入れ、`system.msg` を選ぶ →「既知の形式」タブ →
   **このファイルを .msg として読む**。件数と、各行の文字番号 `[123]` が並ぶ。
5. 絞り込みに `font` と入れ、`bk_font.tms` を選ぶ →「既知の形式」タブ。
   フォント画像が出るので **文字の番号を重ねる** を押す (1 文字 23、1 行 17)。
6. 番号 0 から順に文字を書き出し、`.msg` 読みの「フォントの文字の並び」に貼る。
   もう一度 **.msg として読む** → 日本語になる。文字表は端末に残る。
   - 手で書き写す前に **「文字表の下書きを作る」** を押すと、マスの形に似た字を当てて
     下書きを入れる。**当たりは保証しない**ので、必ず目で確かめて直す道具。
     `.msg` を先に読んでおくと、本文で要る番号だけに絞れる。仮名・数字・記号だけが
     候補なので、漢字のマスには手で書く。画面に **紛らわしい順** が出るので、
     そこから見ると速い。小書きの字 (っ ゃ) と大きい字、濁点・半濁点の有無、
     `0` と `O`、`。` と `゜` は形が近く、実測でもそこを間違えた。
     形で当てたあと **並び順**でも直す。続いたマスが続いた字に当たっていれば、
     その区間は五十音の並びで埋め直すので、小書きや濁点の取り違えはここで消える。
     フォントが五十音順に並んでいなければ支持が集まらず、何も起きない。
   - 全部書き出すのが大変なら、`.msg` 読みの「使われている文字番号」を開く。
     `12=` のような雛形が並ぶので、= の後ろにフォント画像のその番号の文字を書き、
     そのまま上の欄に貼る (番号順の並びでなく **番号=文字の対応表** として読まれる)。
     フォント画像の目盛りでは、その番号が **緑の枠** になり、そのうち文字表にまだ
     無い番号は **橙の枠** になる (要約にも「文字表に無い番号 K 種」と出る)。
     橙が無くなれば「文字表で全部読める」。文字表を貼ったまま「索引ファイル」タブの
     **「報告用の要約を作る」** をもう一度押すと、`[文字表] 貼ってある文字表: N 字 /
     … 文字表に無い K 種` と、先頭 50 件の `.msg` 全体での出来具合が出る
     (`boku2.py check` の `[文字表]` と同じ項目)。
     一括処理なら `python3 tools/boku2.py used ファイル…`。`font.txt` も同じ対応表の
     書き方でよい。
   - 文字表ができたら **「文字表を 16 進表示用のテーブルにする」** も押してみる。
     16 進タブで `.msg` のバイト列がそのまま日本語で見える。これが docs/01 の
     「文字テーブル」を実物で使っている状態 (一括処理なら `boku2.py table font.txt -o boku2.tbl`
     → `python3 tools/hexdump.py system.msg --table boku2.tbl`)。
7. `MAP` のファイルを 1 つ選ぶ →「既知の形式」→ **マップの入れ物を切り分ける** →
   一覧の `1.bin` を選ぶ → **.msg として読む**。`表-行` の番号で会話が並ぶ。
   部品を読んで「これはマップの入れ物です」と出たら (`fish_on_mem.bin` の 11〜16 番など)、
   その部品を選んだまま **もう一度切り分ける**。一括処理 (`text`) は自動で降りる。
8. **校正用の TSV をコピー** で、その場で校正に回せる形になる。

ここまでで「読み方が合っている」ことが確かめられます。

## 2. 一括で取り出す (tools/boku2.py)

画面で確かめた読み方を、全部に適用します。文字表は `font.txt` として保存しておく
(改行はあっても無くてもよい。メモ帳や Excel で保存して先頭に BOM が付いても、
改行が CRLF でも同じに読む)。

```bash
python3 tools/boku2.py unpack 実物/BOKU2.IDX 実物/BOKU2.IMG OUT/
python3 tools/boku2.py maps 実物/MAP/*.* -o OUT/maps
python3 tools/boku2.py text OUT -f font.txt -o all.tsv
```

`text` にフォルダを渡すと、中を辿って `*.msg` (深い所にあるものも) とマップの部品
`1.bin` を全部拾います。ファイルを 1 つずつ渡しても構いません。

Windows のコマンドプロンプト / PowerShell でも `実物/MAP/*.*` はそのまま打って
大丈夫です (シェルは `*` を展開しませんが、道具の側で探します)。
`maps 実物/MAP -o OUT/maps` のようにフォルダを渡しても同じです。

`all.tsv` は `id / offset / size / original / translation` の 5 列。`id` は
`ファイル名:表-行` (マップの会話は `マップ名:表-行`、入れ物の部品は `入れ物名#部品:行`、
入れ物の中の入れ物は `fish_on_mem#11#2:行` のように `#` が重なる) で、
実機で「どのセリフか」を伝えるときの住所になります。

## 3. 校正にかける

```bash
python3 tools/boku2.py fontlist font.txt -o font_chars.txt
python3 tools/proofread.py all.tsv --font-chars font_chars.txt
```

`translation` の列を直したものを同じコマンドにかけると、フォントに無い文字・
半角・行数・用語のずれが機械的に出ます。読み方と着眼点は docs/04。

`all.tsv` は Excel でそのまま開けます (BOM 付き UTF-8 なので日本語が化けない)。
Excel で直して保存し直すときは「Unicode テキスト (*.txt)」でも「CSV UTF-8」でも、
メモ帳の ANSI でも構いません。どの形式でも道具の側が見分けて読みます。

## 報告するとき (何を貼れば次の手が打てるか)

本文 (ゲームのセリフ) は貼らなくてよい。次の 3 つで十分です。

1. `python3 tools/boku2.py check 実物/` の出力全部 (または画面の「報告用の要約」)。
   とくに次の行が決め手になる:
   - `[索引]` の `DFI: 期待どおり` と `名前が付いた N 件`
   - `フォルダの規則: 2 通り (stack / flag) で一致` (食い違いが出たらその行ごと)
   - `[フォント] … 512×… 画素` (幅が 512 なら 1 行 23 字の目盛りが合う)
   - `[文字表] font.txt: N 字 / … 文字表に無い K 種` (文字表を作り始めたら `font.txt` を
     同じフォルダに置く。K が 0 になれば `.msg` の範囲は全部読める。画面では
     「.msg として読む」の欄に貼ってある文字表で同じ行が出る)
   - `位置表の長さの欄: 合う N 件 / 合わない M 件` (8 バイト刻みの後ろ 4 バイトが
     その項目のバイト長か。合わない件数が出たらその行ごと)
   - `[MAP] … 1 番が会話だった N 件 / 会話 M 行`
2. `.msg として読む` を `system.msg` で押したときの要約 1 行
   (`N 件 · 本文あり … · 文字番号の最大 …`)。
3. 何かが `→` で出たら、その行に付いている先頭 16 バイトや 64 バイト。

これだけで、索引・本体・フォント・入れ物・会話の 5 段のどこで外れたかが分かります。

## 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 索引が「候補なし」 | `BOKU2.IDX` の先頭 4 バイトが `44 46 49 00` (DFI) か。違えば別の版 |
| 切り分けた名前が番号だけ | レコードの終わり (種別が 0/1 でなくなる行) の直後に名前が並んでいるか |
| `.msg` が「この形では読めない」 | 先頭 4 バイトが件数 (小さい数) か。入れ物なら先に切り分ける。日記の雛形や保存画面の文言は見出しの無い並び (0x8000 区切り)、保存画面の一部は Shift-JIS (0x00 区切り) で、どちらも自動で試す |
| 文字が `[123]` のまま | 文字表が貼られていない、または短い。「文字番号の最大」より長くする。`text` は終わりに「文字表に無い番号: N 種 (例: …)」と出すので、その番号の文字を足す |
| `check` が「索引と本体が揃っていません」 | 指定したフォルダが ISO のまま (先に展開)、または一段上 (中のフォルダを指定)。どちらも `check` が次の行で教える |
| 文字がずれて別の字になる | フォントの番号の振り方 (1 文字の幅・余白) がずれている。0 番の位置を合わせる |
| `{VOICE 00010001}` が混ざる | 音声の番号。会話ではないので TSV には入れない (`text --keep-voice` で残せる) |
| `maps` で「入れ物ではありません」 | そのファイルの先頭 16 バイトを 16 進で見る。項目数 + (位置, 長さ) の並びでなければ別形式 |
| 「一致するファイルがありません」 | `*.*` の前のフォルダ名が違う (実物/MAP など、吸い出した場所に合わせる)。フォルダをそのまま渡してもよい |

### 診断の `→` の行の読み方

`check` (と画面の「報告用の要約」) が出す `→` は次の 8 種類。上から順に、索引 →
本体 → `.msg` → フォント → 入れ物 の段に対応する。課題 9 で 5 種類は再現できる。

| `→` の行 | どの段 | 意味と次の手 |
| --- | --- | --- |
| 索引と本体が揃っていません | 入口 | 指定したフォルダに `BOKU2.IDX` / `BOKU2.IMG` が無い。ISO のままか一段上 (次の行で教える) |
| 先頭が DFI でないので、この道具の索引の読みは使えません | 索引 | 先頭 4 バイトが `44 46 49 00` でない。別の版か、ファイルの取り違え。添えた 64 バイトを報告 |
| 名前が付かないファイルが多い | 索引 | レコードの直後に名前が並んでいない。添えた 64 バイトを報告 (名前の置き場の推定が外れている) |
| 同じ名前があります | 索引 | フォルダの入れ子の復元が外れて、別フォルダの同名ファイルが衝突した。`~2` を付けて残してある |
| フォルダの規則が 2 通りで食い違うファイル N 件 | 索引 | こちらの規則と公開ソースの規則で道筋が違う。どちらが正しいかは実物でしか決まらない。その行ごと報告 |
| 読めない .msg の例: … 先頭 16 バイト … | `.msg` | 「件数 + 位置表」の形になっていない。入れ物なら先に切り分ける。16 バイトを報告 |
| [フォント] … は TIM2 として読めません | フォント | `0x80` の位置に `TIM2` が無い。前置きの長さが違うか、圧縮。16 バイトを報告 |
| 入れ物として読めないファイルの例 | 入れ物 (MAP) | 「項目数 + (位置, 長さ)」の並びでない。名前と 16 バイトを報告 |

## 練習用データでの答え合わせ

`work/BOKU2SAMPLE/answer.tsv` に、取り出せるはずの全文があります。
`all.tsv` の `original` と一致すれば、手順が正しく通っています。
