## 最大の発見: 先行事例のソースが公開されていた (壁の正体の訂正)

**英語翻訳パッチが既に存在する** (Hilltop Works, 2023年11月公開、約 5,000 行)。
報道記事からは「独自の圧縮を書いた」「縦書き」としか分からなかったが、
**ツールのソースが GitHub で公開されていた** (HilltopWorks/BokuNoNatsuyasumi2:
`UNPACK.py` / `MSG.py` / `textCompaction.py` / `asm_notes.txt`)。読んで分かったこと:

1. **テキストは圧縮されていない。** 記事の「圧縮」は、英訳を元の容量に収める
   ために向こうが書いた **文字列の詰め込み (textCompaction.py)** のこと。
   ディスク上の `.msg` は素の「件数 + 位置表 + 本文」。
2. **文字コードはフォント画像の並び順。** 本文は 2 バイトの並びで、値は
   `bk_font.tms` の何番目の文字か (1 行 23 文字。`asm_notes.txt` の `char%17` は
   0x17 = 23 のこと。reprint.py の `N_COLUMNS = 23` で確定)。
   制御コードは `0x8000` 終わり / `0x8001` 改行 / `0x8002 + u16` 待ち /
   `0xCDCD` 詰め物。**Shift-JIS ではないから、生検索で出なかった。**
   → これは docs/03 で教えている「テーブル」の実物そのもの。
3. **索引 (DFI) の名前は、レコードの直後に順番どおりに並ぶ**だけだった。
   +4 の値は名前の位置ではない (向こうも読むだけで使っていない)。
   先頭は根 "/"。+2 の u16 は「同じフォルダにまだ続くか」で、フォルダの
   入れ子はこれで復元できる (フォルダで 0 なら、それが親の最後の項目)。→ **`#N` 表示の宿題はこれで解けた。ユーザーの
   バイト提供を待つ必要が無くなった。**
4. `.msg` の位置表は IMG 内のものが 8 バイト刻み、マップ内の表が 4 バイト刻み。
   マップ (`map/*.*`) は `[u32 0xE][u32 表の長さ 0x80]` + (位置, 長さ) の対の入れ物で、
   その 1 番のファイルに `[u32 表の数][0xC の項目]` で会話の表が入る。
5. 縦書きは **表示ルーチン側** の話 (向こうは MIPS を書き換えて横書きにした)。
   データの並びは素直。

参照 (すべて公開情報。ソースを読んで **形式を学んだ** だけで、向こうのデータ
ファイルや訳文はこのリポジトリに入れていない):

## 次の一手 (優先順)

0. **まず診断して出力を貼る。** `python3 tools/boku2.py check 吸い出したフォルダ/`、
   またはブラウザの「索引ファイル」→ 解析 →「報告用の要約を作る」。本文は含まない。
1. **索引タブで切り分け → 一覧の絞り込みに `msg` と入れる。** 名前が
   `system/system.msg` のように出るはず。出なければ `#N.種類` に戻るので報告。
2. **`system.msg` などを選び、「既知の形式」→「.msg として読む」。**
   件数と各行の 2 バイト番号が並ぶ。番号の最大値がフォントの文字数の目安。
3. **`bk_font.tms` を選び「既知の形式」タブで「文字の番号を重ねる」** (刻み 22 ドット、
   1 行 23 字。既定値のまま。列数は画像の幅から自動で決まる)。番号順に文字を書き出して .msg 読みの欄に貼ると、日本語で読める。
   これが「テーブル作り」。
4. **物語の会話は `MAP` フォルダ。** `MAP/M_A11000.*` のようなファイルを選び、
   「既知の形式」→「マップの入れ物を切り分ける」→ `1.bin` を選んで「.msg として読む」。
   `0.bin` はイベントの命令列 (会話ではない)。
5. 読めたら **「校正用の TSV をコピー」** → ファイルに貼って
   `python3 tools/proofread.py そのファイル --no-font-check`。docs/04 の校正の練習へ。
6. 画面で確かめた読み方が合っていたら、**全部を一括で**:
   `python3 tools/boku2.py unpack BOKU2.IDX BOKU2.IMG OUT/` →
   `python3 tools/boku2.py maps MAP/*.* -o OUT/maps` →
   `python3 tools/boku2.py text OUT/system/*.msg OUT/maps/*/1.bin -f font.txt -o all.tsv`
   (font.txt は文字表を保存したもの)。Windows でも `MAP/*.*` はそのまま打ってよい
   (道具側で展開する)。
7. (任意) PCSX2 は「動いている状態の確認」用に残す。必須ではない。

## 未解決の技術課題 (ツール側)

- 実データで名前の並びが本当に順番どおりか、社長の環境での確認待ち
  (Hilltop の展開器がそれで動いているので、外れる可能性は低い)。
- ~~フォルダの閉じ方の規則~~ → **#108 でほぼ決着**。2 つの規則 (stack / flag) は
  フォルダが 3 段以上まとめて閉じるときだけ答えが変わる。小さな形を 816 通り
  総当たりすると 34 通りで食い違い、**その 34 通りすべてで公開ソースの実物のコードは
  flag と同じ答え**を出した (向こうの `unpackIMG` を合成索引に対して実際に走らせた)。
  向こうの道具は実物で動いて英語版パッチを出しているので、「flag が正しい」か
  「実物にこの形が出てこない」かのどちらか。どちらにしても**裏付けがあるのは flag
  だけ**なので、CLI も画面も既定を flag にした。`check` は今も両方で突き合わせるので、
  実物で食い違えばその場で分かる (残っているのはその確認だけ)。

  - `unpack BOKU2.IDX BOKU2.IMG OUT/` で索引どおりにフォルダ付きで切り分け
  - `maps MAP/*.* -o OUT/maps` で入れ物を部品に
  - `text ファイル… -f font.txt -o all.tsv` で会話を校正用 TSV に。入れ物・表の一覧・
    単体 .msg を自動で見分け、id は `ファイル名:表-行`

    → `proofread.py all.tsv --font-chars font_chars.txt` でフォントに無い文字の検査まで通る
  - テスト: 実物と同じ形の合成データ (入れ子のフォルダ・空フォルダ規則・音声つきの
    表・入れ物) で unpack → maps → text → proofread を通し、**索引の読みは Node
    (ブラウザ側) と Python が同じ答えを出す**ことを突き合わせた。
- 次に見るべきこと: 実データで `unpack` の件数 (画面と同じ 1951 前後) と、
  `maps` が MAP フォルダの全ファイルで通るか。通らないファイルがあれば
  その先頭 16 バイトが次の手がかり。

### #5 — 物語の会話がある場所 (MAP の入れ物) を読めるようにした

- 辛口ユーザー: 「`.msg` を読めても、出てくるのはメニューの文言だけ。物語の

- 辛口クリエイター: 「公開ソースには MAP の入れ物と表が複数の会話ファイルの

- 対応 (公開ソースの `unpackMap` / `unpackMapMSG` / `readMSG(MAP_MODE)` に合わせた):

  JMPM / MAP / WAT / ANM …) の解読結果なので、0 番はイベントスクリプトと分かっている。

### #3 — 名前が無くても `.msg` の候補に辿り着けるように

- 辛口ユーザー: 「切り分けた 1951 個が `#0 #1 …` の番号だけ。`msg` で探しても
  出ない。一覧に絞り込み欄すら無い」
- 辛口クリエイター: 「名前解決はユーザーのバイト提供待ちで止まっている。
  待つ間に **名前に頼らない道** を作らないと、この宿題が全体を止める」
- 対応:
  - **中身から種類を付ける `sniffKind`** を追加。魔法数 (TIM2 / VAGp / RXWS /
    SShd / ELF / MPEG / DFI / RIFF / PNG) で確実に当て、無ければバイトの性質から
    見当を付ける。番号だけの名前には `#0012.tm2` のように末尾へ付く。
  - **圧縮の見当**: 先頭 u32 が「自分より大きく 32 倍以内」なら伸張後の大きさと
    見て `packed`。圧縮テキストのゲームでは `.msg` はここにある見込み。
  - 切り分け後に「中身の見当: tm2 1200 · packed 400 …」と集計を表示。
  - **ファイル一覧に絞り込み欄** (`msg` / `packed` / `.tm2`、空白区切りで AND)。
  - テスト: `tests/test_sniff.mjs` (魔法数 8 種・圧縮の見当・性質・集計) と
    ヘッドレスブラウザで PACK.IDX/IMG を切り分け → 22 件全部に種類が付き、
    絞り込みが効くことを確認。
- 次に見るべきこと: 実データで `packed` の件数と大きさの分布。数十 KB 台の
  `packed` が数百個なら、それが `.msg` 群 (会話ファイル) の可能性が高い。
- **後日訂正 (#4)**: テキストは圧縮ではなかった。`.msg` は先頭が件数なので `packed`
  ではなく `bin` に分類される。`packed` の見当そのものは一般用として残す。
