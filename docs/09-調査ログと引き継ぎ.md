## 現在地 (2026-09 時点)

対象: 僕の夏休み2 (PS2 / SCPS-15026)。吸い出し済みフォルダを構造探査台で解析中。

判明済み:

- ルート `SYSTEM.CNF` → 本体 `SCPS_150.26` (ELF32 / MIPS R5900) を逆アセンブル可能に
- `BOKU2.IDX` は独自形式 **"DFI"**。構造を逆アセンブルとバイト解析から確定:
  - ヘッダ 16 バイト (`DFI\0` + 版 0x100)
  - レコード 16 バイト: +4 名前位置 / +8 セクタ番号(×2048) / +12 長さ(バイト)
  - 本体プログラム 0x001293D8 の関数が「先頭が DFI ならバッファ+0x10 を先頭とする」
    と書いていたのと一致
- 索引を読んで `BOKU2.IMG` を **1951 ファイルに切り分け**られた
- 切り分けた先頭のかたまりは全部 `TIM2` (画像)。`00diary` の日記写真 (`nik***.tm2`)

## 最大の発見: 先行事例と「壁」の正体

**英語翻訳パッチが既に存在する** (Hilltop Works, 2023年11月公開)。約 5,000 行を翻訳。
ここから技術的な核心が分かった。

1. **テキストは圧縮されている。** 翻訳者本人が「独自の圧縮システムを書く必要が
   あった」と明言。→ **生の `BOKU2.IMG` を日本語で全体検索しても `.msg` が
   見つからないのは、これが理由。** ずっと当たっていた壁の正体が確定した。
2. **テキストは縦書きで格納されている。** 横表示にするため MIPS アセンブリで
   表示ルーチンを書き換えたとのこと。文字の並びが素直でない。
3. **romhacking.net に PS2 翻訳の完全チュートリアル**があり、ファイル抽出・
   テキスト発見・MIPS・デバッガでのテキストルーチン特定・圧縮伸張まで手順化。

参照:

- Hilltop Works 英語パッチ (PC Gamer / Time Extension / Kotaku が報道)
- readonlymemo.com の Hilltop インタビュー
- romhacking.net PS2 Translation Tutorial (documents/919)
- romhacking.net LZSS Compression FAQ (documents/281)

## この発見が意味すること

- 目的が **学習** なら、この題材はむしろ最良の教材。難所 (圧縮・縦書き・
  独自索引) が全部そろっていて、しかも先人の答え合わせができる。
- 目的が **テキスト現物の取得** なら、圧縮を解くのが必須。ディスク上の圧縮を
  自力で解くのは、熟練者が 11 か月かけた仕事の一部。現実的ではない。
  → **PCSX2 でゲームを動かし、展開後のメモリを見る**のが唯一の近道
    (docs/08-コードを読む.md、docs/05-実物のディスクを扱う場合.md 参照)。
    メモリは既に伸張済みなので、圧縮を解く必要がそもそも無い。

## 次の一手 (優先順)

1. **PCSX2 でメモリダンプ → 探査台に読ませる。**
   - メインメモリ範囲 0x20000000〜0x21FFFFFF
   - ゲームを会話シーンまで進めてダンプ → その中に展開済みの日本語がある
   - これが圧縮の壁を迂回する正攻法
2. **切り分けた画像 (`.tm2`) を「見つけた絵」タブで見る。** 圧縮されていないので
   今すぐ見られる。フォント `bk_font.tms` もここ。
3. **索引の名前解決の改善 (ツール側の宿題)。** いまは切り分け結果が `#N` 表示。
   名前が出れば `.msg` を名前で探せる。要 `BOKU2.IDX` の 0x8100 付近のバイト。

## 未解決の技術課題 (ツール側)

- `readDfi` の名前解決: 実データで名前ポインタが解決せず `#N` になる。
  名前置き場の実バイト (0x8100〜0x8250) があれば直せる。
  → セクタ/長さでの切り分けは正しく動いているので、抽出自体は問題ない。
