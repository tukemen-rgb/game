## 現在地 (2026-09 時点)

対象: 僕の夏休み2 (PS2 / SCPS-15026)。吸い出し済みフォルダを構造探査台で解析中。

判明済み:

- `BOKU2.IDX` は独自形式 **"DFI"**。構造を逆アセンブルとバイト解析から確定:
  - ヘッダ 16 バイト (`DFI\0` + 版 0x100)
  - レコード 16 バイト: +4 名前位置 / +8 セクタ番号(×2048) / +12 長さ(バイト)
  - 本体プログラム 0x001293D8 の関数が「先頭が DFI ならバッファ+0x10 を先頭とする」
    と書いていたのと一致
- 索引を読んで `BOKU2.IMG` を **1951 ファイルに切り分け**られた
- 切り分けた先頭のかたまりは全部 `TIM2` (画像)。`00diary` の日記写真 (`nik***.tm2`)

## 最大の発見: 先行事例のソースが公開されていた (壁の正体の訂正)

**英語翻訳パッチが既に存在する** (Hilltop Works, 2023年11月公開、約 5,000 行)。
報道記事からは「独自の圧縮を書いた」「縦書き」としか分からなかったが、
**ツールのソースが GitHub で公開されていた** (HilltopWorks/BokuNoNatsuyasumi2:
`UNPACK.py` / `MSG.py` / `textCompaction.py` / `asm_notes.txt`)。読んで分かったこと:

1. **テキストは圧縮されていない。** 記事の「圧縮」は、英訳を元の容量に収める
   ために向こうが書いた **文字列の詰め込み (textCompaction.py)** のこと。
   ディスク上の `.msg` は素の「件数 + 位置表 + 本文」。
2. **文字コードはフォント画像の並び順。** 本文は 2 バイトの並びで、値は
   `bk_font.tms` の何番目の文字か (1 行 17 文字、`asm_notes.txt` の `char%17`)。
   制御コードは `0x8000` 終わり / `0x8001` 改行 / `0x8002 + u16` 待ち /
   `0xCDCD` 詰め物。**Shift-JIS ではないから、生検索で出なかった。**
   → これは docs/03 で教えている「テーブル」の実物そのもの。
3. **索引 (DFI) の名前は、レコードの直後に順番どおりに並ぶ**だけだった。
   +4 の値は名前の位置ではない (向こうも読むだけで使っていない)。
   先頭は根 "/"。+2 の u16 は「同じフォルダにまだ続くか」で、フォルダの
   入れ子はこれで復元できる (フォルダで 0 なら、それが親の最後の項目)。→ **`#N` 表示の宿題はこれで解けた。ユーザーの
   バイト提供を待つ必要が無くなった。**
4. `.msg` の位置表は IMG 内のものが 8 バイト刻み、マップ内の表が 4 バイト刻み。
   マップ (`map/*.*`) は `[u32 0xE][u32 表の長さ 0x80]` + (位置, 長さ) の対の入れ物で、
   その 1 番のファイルに `[u32 表の数][0xC の項目]` で会話の表が入る。
5. 縦書きは **表示ルーチン側** の話 (向こうは MIPS を書き換えて横書きにした)。
   データの並びは素直。

参照 (すべて公開情報。ソースを読んで **形式を学んだ** だけで、向こうのデータ
ファイルや訳文はこのリポジトリに入れていない):

## この発見が意味すること

- **PCSX2 のメモリダンプは不要になった。** ディスク上の `.msg` をそのまま読める。
- 学習の本題 (テーブル作り → 抽出 → 校正) に、実物でそのまま入れる。
- 以前の記述「テキストは圧縮」は誤り。LZSS の道具は一般用として残す。

## 次の一手 (優先順)

0. **まず診断して出力を貼る。** `python3 tools/boku2.py check 吸い出したフォルダ/`、
   またはブラウザの「索引ファイル」→ 解析 →「報告用の要約を作る」。本文は含まない。
1. **索引タブで切り分け → 一覧の絞り込みに `msg` と入れる。** 名前が
   `system/system.msg` のように出るはず。出なければ `#N.種類` に戻るので報告。
2. **`system.msg` などを選び、「既知の形式」→「.msg として読む」。**
   件数と各行の 2 バイト番号が並ぶ。番号の最大値がフォントの文字数の目安。
3. **`bk_font.tms` を選び「既知の形式」タブで「文字の番号を重ねる」** (1 字 23 ドット、
   1 行 17 字)。番号順に文字を書き出して .msg 読みの欄に貼ると、日本語で読める。
   これが「テーブル作り」。
4. **物語の会話は `MAP` フォルダ。** `MAP/M_A11000.*` のようなファイルを選び、
   「既知の形式」→「マップの入れ物を切り分ける」→ `1.bin` を選んで「.msg として読む」。
   `0.bin` はイベントの命令列 (会話ではない)。
5. 読めたら **「校正用の TSV をコピー」** → ファイルに貼って
   `python3 tools/proofread.py そのファイル --no-font-check`。docs/04 の校正の練習へ。
6. 画面で確かめた読み方が合っていたら、**全部を一括で**:
   `python3 tools/boku2.py unpack BOKU2.IDX BOKU2.IMG OUT/` →
   `python3 tools/boku2.py maps MAP/*.* -o OUT/maps` →
   `python3 tools/boku2.py text OUT/system/*.msg OUT/maps/*/1.bin -f font.txt -o all.tsv`
   (font.txt は文字表を保存したもの)。
6. (任意) PCSX2 は「動いている状態の確認」用に残す。必須ではない。
